# 研究笔记

保存资料摘记、待验证假设和实验观察，方便后续研究者追溯来源，不把上游宣称或设想写成实测结论。知识分工归 [owning SPEC](../SPEC.md)，导航见 [上级索引](../README.md)。目前没有已提交的研究结论。

## 如何新增

按日期与主题新建 Markdown 文件。输入可以是网页、论文、固定版本源码或实际运行记录；输出要分清来源陈述、个人假设、观察与有条件的结论。缺少证据时保留待验证，不必为填满模板编造结论。

精简结构示例（占位字段不是已完成研究）：

~~~markdown
# <日期 · 研究问题>
- 状态：草稿
- 验证状态：待验证／资料阅读／源码阅读／运行验证（按实际选择）
- 来源版本：URL、论文／文档版本；源码填仓库、完整 commit SHA 与路径
- 访问日期：YYYY-MM-DD（可变网页必填）
- 适用条件：机器、平台、模型身份与运行时；未涉及运行则写不适用

## 来源陈述
<原文摘要、定位信息；标明这是来源的主张>
## 假设与推断
<要检验什么，哪些条件尚未确认>
## 观察与证据
<实际观察；运行记录链接或“尚未运行”>
## 结论与限制
<有证据才下结论，说明适用范围；否则写待验证>
## 下一步与相关规格
<验证入口；需持久化的边界变更指向 owning spec>
~~~

测量定义与证据格式分别引用 [测量 SPEC](../../benchmarks/SPEC.md) 和 [运行记录模板](../../benchmarks/run-template.md)，不在笔记中另设标准。持久决策及理由更新 owning spec；笔记可以保留假设演进，不替代规格。公开前检查引用许可和敏感信息，不附权重或无权分享的数据。
