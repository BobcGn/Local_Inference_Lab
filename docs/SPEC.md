# 知识记录与规格维护

## 文档分工

规格是目标、边界、契约及其取舍的唯一权威归属；README 是使用与导航入口；贡献指南说明协作操作；运行记录保存测量事实；研究笔记保存资料、假设和观察。不能把计划或未经验证的上游宣传写成既成能力。

`architecture/` 解释特定版本运行时的数据流和资源生命周期，不另建一份与根架构竞争的项目边界。`research-notes/` 区分来源、假设、观察和结论。`decisions/` 提供决策检索与历史引用，持久决策及原因仍归 owning spec，不复制相同理由。

## 可追溯性

外部实现说明记录仓库、完整提交和相关路径；可变网页注明访问日期及验证状态。由实测支持的结论指向运行记录与适用条件。只读到源码的结论标为源码阅读，不冒充运行验证。

## 规格生命周期

新增或推断的规格保持 draft；推断在正文相应位置标为未确认。用户确认意图不等于已审阅整份生成文本，审阅通过的长期规格才转为 active。新增真实边界用独立 id 和 parent；跨模块关系由父规格维护。修改范围或契约时同改 owning spec，并检查链接。

## 发布边界

不提交密钥、个人敏感信息、无权分享的输入、模型权重或上游构建产物。仓库没有顶层 LICENSE 时，不自行宣称存在统一开源许可；新增许可由维护者另行决定。
