# 实验设计契约

## 职责

每个实验界定研究问题、对照条件、固定输入、操作入口与验收证据。编号是阅读与执行路线，不是软件发布阶段，也不代表前一实验的模型必须适配后一运行时。

01 建立 Mellum2.1 MLX 常规推理基线；02 对比同 GGUF 的 CPU／Metal；03 在兼容小 GGUF 上验证 DiskInfer CPU 流式读取；04 验证兼容 MoE 运行时的专家卸载。四条路线共享固定文本输入，但不能预设不同分词器和模板产生相同 token 序列。

## 有效性边界

实验必须将“可加载并生成”“任务回答可检查”“机制确实生效”“性能收益”分开验收。只运行常规模式，不能给出流式读取或专家卸载有效的结论。输出 token 相同也不等于任务回答正确。

改变模型、量化、模板或构建时显式列出混杂变量。修改固定提示词后，旧结果仍引用旧提交，不与新输入结果无说明地合并。Thinking token 占用输出预算；截断或没有最终回答必须如实记录。

## 当前兼容性限制

03 尚未固定 DiskInfer 提交、兼容小模型或 macOS 运行路径；04 尚未固定运行时、checkpoint 及专家布局兼容性。不得为它们提供未经验证的“一键可用”承诺。03 先用小模型的原因是隔离正确性与平台问题，而非证明大模型已经可行。

## 状态与完成条件

状态说明必须指向提交的运行证据；没有结果时保持待运行／待验证。失败和未测项目不能删去以满足验收。实验步骤归各实验 README，运行记录归 benchmarks，设计取舍归 owning spec。
