# 实验入口

本目录用于验证 DiskInfer 所启发的低内存运行大模型思路在 Mac／Windows 上的可行性，不是产品或平台支持承诺。维护者主线是 macOS M5、32 GB 统一内存；Windows 研究由朋友在自己的机器上独立负责。

**当前实验尚未开始**：这里只有方案、固定输入和手动命令，没有已提交实测结果、测量代码或自动化流水线。维护者报告已下载模型，本工作树不包含模型文件，运行前仍须核对。范围和边界以 [目标](../goal-and-requirements.md)、[架构](../architecture.md) 和 [实验契约](SPEC.md) 为准。

| [02 · CPU／Metal 基线](02-llama-metal/README.md) | 同一 M5、同一 GGUF 的后端对照 | 固定源码与手动入口已有；待验证 |
| [03 · DiskInfer CPU 流式读取](03-disk-streaming/README.md) | 小 GGUF 上的有限 arena 与实际流式读 | commit、小 GGUF、macOS 运行路径均未选定；待验证 |
| [04 · MoE 专家卸载](04-moe-expert-offloading/README.md) | 同权重常驻／专家卸载对照 | runtime、checkpoint、专家布局均未选定；待验证 |
| [Windows 独立验证](../docs/windows-validation.md) | 先验证本机常规 CPU，再研究流式可行性 | 朋友负责；尚无本机证据，CPU 入口不等于流式验证 |

macOS 建议先 01，再 02，之后分别推进 03 和 04 的兼容性检查。编号是路线，不是已完成阶段；不要求 Mellum 一直用于后续实验。Mellum 因 MoE 结构成为初始样本，“最优选”尚未证明。通用权重流式读取与按路由加载专家不是同一机制，03 成功不能替代 04 的验证，反之亦然；边界见 [架构](../architecture.md)。

## 开始一次实验

1. 阅读对应实验的前提，按 [模型说明](../models/README.md) 与 [源码说明](../repos/README.md) 核对身份；未固定的候选先做兼容性检查，不直接进入性能结论。
2. 共用 [三个固定文本输入及人工检查说明](01-mlx-baseline/prompts/README.md)。保留输入原文，记录实际模板、分词和输出预算；不要假定跨运行时 token 序列相同。
3. 从 [运行记录模板](../benchmarks/run-template.md) 创建记录，保存完整命令、原始日志、输出和环境。步骤目前需手动执行，不能假定已有计时或采样脚本。
4. 按 [测量口径](../benchmarks/README.md) 和 [证据契约](../benchmarks/SPEC.md) 整理逐次结果，分别报告加载／生成、回答可检查性、机制证据和性能；一次生成成功不等于其余项目通过。

## 输入、产物与失败记录

- 输入：模型及校验身份、运行时及构建身份、固定提示词、模板与参数、缓存／arena／专家缓存条件。各实验补充自己的选择项。
- 输出：运行记录与可分享证据放入 [benchmarks](../benchmarks/README.md)，按内容归入已有的 `correctness/`、`memory/`、`throughput/`。大文件可以留本地，但分享结论须提供必要摘要、日志或获取方法，不能仅贴本地路径。
- 失败也产出记录：写明卡在下载、构建、加载、生成、兼容性还是机制观测；保存完整命令、退出状态／错误日志、最后可完成步骤及复现条件。OOM、超时、截断、只有 Thinking 没有最终回答都不删去。
- 尚未运行写“未运行”；缺指标写“未测”及原因；没有足够证据写“未验证”，不把未测记成零或用性能数字替代机制验收。后续重跑另存记录并关联原失败，不覆盖原始结果。
