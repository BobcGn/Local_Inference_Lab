# 04 · MoE 专家卸载

验证按路由加载专家权重能否降低内存占用，并测量专家缓存预算的代价。**状态：待验证；运行时、checkpoint、专家布局尚未选定，没有实测结果或自动化实现。**

[实验索引](../README.md) · [实验契约](../SPEC.md)

本实验与 [03 的通用权重流式读取](../03-disk-streaming/README.md) 分开验收；机制边界见 [架构](../../architecture.md)。Mellum 因 MoE 成为初始样本，但兼容性与“最优选”都未经证明。

## 前提与输入

维护者先在 macOS M5、32 GB 统一内存上研究候选方案，不承诺 Metal 或其他后端已有可用路径。Windows 由朋友独立研究，见 [Windows 入口](../../docs/windows-validation.md)。

- 运行时：选择候选并按 [源码说明](../../repos/README.md) 记录完整 commit、构建条件及修改。上游文档只作为查阅入口，不等于本机验证。
- 权重：核对实际专家层实现、张量命名、量化及存储布局。若研究 vLLM Metal，核查选定版本对 MLX-LM `SwitchGLU` 和 safetensors 布局的具体支持，不预设 Mellum 兼容。布局不兼容时先换用运行时明确支持的 checkpoint，并按 [模型说明](../../models/README.md) 记录身份。
- 请求与缓存：使用 [三个固定文本输入](../01-mlx-baseline/prompts/README.md)，固定模板、采样、上下文、并发和输出预算；明确常驻条件及各专家缓存预算。

## 入口：兼容性检查

当前没有可照抄的运行命令。先固定 runtime／checkpoint／layout 组合，找到其真实常驻与卸载入口，再把实际命令、配置、源码位置及检查结果写入记录。不要为未验证的组合发明开关或一键脚本。

1. 建立兼容性清单：架构、专家张量映射、量化、文件布局及后端支持。把源码阅读和本机运行观察分别标注。
2. 确认同一份权重能以常驻和卸载两种条件加载并生成；如果只有常驻模式可用，本轮只记录兼容性进度。
3. 确认可获得专家请求、缓存命中／缺失、读取及驻留证据；若需插桩，明确尚待实现的观测项。仅有参数名称或内存下降不足以确认按路由卸载。

## 对照步骤与输出

1. 在同一运行时、同权重下比较常驻／卸载，固定请求条件，从日志或仪表确认实际行为。
2. 先试可容纳于本机的专家缓存预算，再改变预算；分别保留 prefill／decode 的缓存命中与缺失、读量、延迟、吞吐、内存和原始输出。
3. 比较 token ID 或注明文本粒度，保存首个分歧及条件；按 [提示词说明](../01-mlx-baseline/prompts/README.md) 另做回答检查。Thinking 耗尽预算或缺少最终回答如实留档。
4. 输出为 [运行记录](../../benchmarks/run-template.md)、兼容性清单、命令／配置与日志、卸载机制证据、输出对照及指标汇总。次数与测量定义见 [基准测量口径](../../benchmarks/README.md)，归档见 [实验索引](../README.md)。

## 验收与失败记录

- 可运行与回答：两种条件均可加载生成，三题最终回答可检查，人工判断与一致性比较分列。
- 机制：专家卸载实际生效，有可复现的布局检查和驻留／读取／缓存观测，而非只启用了某个选项。
- 性能：同权重对照可重复，再据测量讨论是否节省内存及其 I/O 代价；不要求结果必须更好，也不将本组合结果推广到所有 MoE 或 Windows。

布局不匹配、checkpoint 不支持、仅常驻可用、观测缺失、OOM、读取错误或输出分歧都按 [失败记录指引](../README.md#输入产物与失败记录) 保存。写明未选定／不兼容／未测的具体项，不把换模型后的结果混为同权重对照。
