# 固定输入与人工检查

这三个 UTF-8 文本是实验 01–04 共用的自然语言输入，不是自动评分程序。运行时读取对应 `.txt` 原文；不要为让某个模型通过而修改输入或悄悄增加提示。检查时保留仓库提交、提示词文件、实际聊天模板及原始输出。入口见 [实验索引](../../README.md)，有效性要求见 [实验契约](../../SPEC.md)。

## 逐题检查

| 输入 | 人工检查要点 |
| --- | --- |
| [page-cache.txt](page-cache.txt) | 是否用三句话解释文件页缓存，并给出重复读取同一文件的例子；是否说明缓存位于内存、重复读取可能命中缓存而减少磁盘访问。不能声称每次重复读取都必然命中，或把应用读取字节等同于 SSD 读取字节。内容正确性与“三句话”的格式遵守分开记录。 |
| [cpp-reference.txt](cpp-reference.txt) | 是否指出按值传参会复制 `vector`，局部 `push_back(42)` 不改变调用者的容器；若要修改调用者，签名可改为 `void add(std::vector<int>& values)`，并解释非 const 引用关联原对象。 |
| [issue-triage.txt](issue-triage.txt) | 是否给出以换行符结尾的最小复现输入（例如明确标注字节／转义的 `a\n`）、两条可执行排查步骤和一个回归用例；是否区分解析器产生的末尾空段与界面计数逻辑，并说明预期来自何种产品约定。 |

**行数没有脱离产品语义的唯一答案。** `issue-triage` 未规定末尾空段是否算一条导入记录；应检查回答是否明确假设，并按该约定给出一致的预期及回归用例。不能只因它选择的行数与评阅者偏好不同就判错；也不能把某一种字符串分割行为当成已经确定的根因。

## 长度、Thinking 与输出对照

- 首轮短预算只检查加载与开始生成，不据此判定任务回答正确。正式运行先试跑确定预算，再对同一对照组固定；若修改预算，另记一组条件。
- Thinking 会占用生成预算。保存原始输出，标出停止原因、是否截断、是否有完整最终回答；仅有推理片段不能算已回答。不要删掉 Thinking 后假装输出未达到上限。
- 每题分别记“完整且可检查／不完整／未作答”、内容判断、格式遵守与理由；这些是人工检查项，不是已有的自动评分结果。
- token 一致性与回答正确性分开：相同输出也可能答错，数值或措辞差异也不必然意味着机制错误。同权重对照的 token ID／文本粒度和首个分歧按 [测量口径](../../../benchmarks/README.md) 记录；不同分词器、模板、量化的输出不能直接当逐 token 等价对照。
