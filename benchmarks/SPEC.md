# 测量口径与证据契约

## 职责

把一次观察变成能复现、能比较、能反驳的证据。运行记录关联环境、模型、运行时、完整命令、输入、模板、采样、缓存条件与原始输出；缺失项写“未记录／未测”及原因，不能把空缺写为零。

## 计时与统计

模型加载与已加载请求计时分开。TTFT 从请求处理开始到首 token 可用；只有文本块时标为首文本块延迟。异步／惰性执行以实际求值或同步完成为准。Prefill 使用输入 token 数和对应耗时；自定义 decode 用首末 token 间隔与 N−1 个 token，N 小于 2 时未测。框架原始指标必须保留来源和定义，不冒充自定义口径。

正式组每个条件预热一次，至少测三次，保存逐次值、中位数和实际 token 数。首次加载或冷缓存实验单独标识，不能预热后宣称是冷启动。Thinking token 计入生成长度。不能从总 CLI 耗时倒推出 TTFT。

## 资源与正确性

分别标记 RSS、分配器峰值、系统压力和交换量，附单位与采样工具；它们不互相替代，也不无说明相加。应用层读量与设备读量分开，`pread` 字节不等于 SSD 读量。重启进程不证明页缓存为空；缓存控制未验证时如实标记未知。

在同权重、模板、采样下优先比较 token ID，保存首个分歧；只能取文本时注明粒度。不同后端可能产生数值差异，不能仅凭一次分歧判定算法错误。专家卸载的命中／缺失、读量按 prefill 和 decode 分开。

## 证据边界

原始结果不可为改善中位数而删除；失败、截断、未测指标和比较限制一起提交。较大的原始文件可留本地，但分享的结论必须能追到可分享的必要日志、摘要或获取方法。本地路径本身不是其他人可审查的证据。敏感信息去标识时说明删改范围，不能改写测量事实。
